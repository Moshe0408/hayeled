# מדריך הגדרה למנהל: לוח ניהול, נתונים, משובים ופרסומות

> המדריך מיועד לבעל המשחק **הילד מהשכונה**. הוא מסביר צעד אחרי צעד איך מחברים שרת (Supabase, חינמי), נכנסים ללוח הניהול, מקבלים משובים ומפעילים פרסומות בעתיד.

## בקצרה: מה צריך לדעת

1. **צריך מייל?** לא. כל משוב שמגיע מופיע בלוח הניהול, בלשונית "משובים". מייל צריך רק אם רוצים **גם** לקבל הודעה לתיבת הדואר על כל משוב חדש. זה אופציונלי ומוסבר בשלב 6.
2. **קישור ללוח הניהול:** https://moshe0408.github.io/hayeled/admin.html
   אין אליו קישור מתוך המשחק, וגוגל לא מאנדקס אותו. הכניסה דורשת אימייל וסיסמה של מנהל.
3. **פרסומות כבויות** עד שמפעילים אותן בלשונית "הגדרות ופרסומות" בלוח הניהול. אין צורך לשנות קוד ואין צורך להעלות גרסה.
4. **המשחק עובד גם בלי שרת.** כל עוד `js/config.js` ריק, המשחק עובד כרגיל, בלי סטטיסטיקות, בלי משובים ובלי פרסומות מהשרת. ההתקדמות של השחקנים נשמרת תמיד במכשיר שלהם, גם בלי שרת.

**מה רואים בלוח הניהול:** כמה מחוברים עכשיו, כמה שחקנים יש בסך הכול, כמה נכנסו היום / השבוע / החודש, כמה התקינו למסך הבית, כמה קריירות התחילו, כמה משחקים שוחקו, כמה עונות הושלמו, כמה פרשו, איזה לאום / עמדה / מועדון בוחרים הכי הרבה, דירוג ממוצע, כל המשובים, ונתוני פרסומות.

**סדר העבודה:** שלב 1 → 2 → 3 → 4 → 5 (בערך 15 דקות). שלבים 6-8 אופציונליים.

## שלב 1: יצירת פרויקט Supabase חינמי

1. היכנס ל-https://supabase.com ולחץ **Start your project**. אפשר להירשם עם חשבון GitHub (`Moshe0408`) או עם מייל.
2. לחץ **New project**.
   - **Name:** `hayeled`
   - **Database Password:** לחץ Generate ו**שמור את הסיסמה במקום בטוח** (מנהל סיסמאות). לא תצטרך אותה ביום-יום, אבל בלעדיה קשה לשחזר גישה למסד הנתונים.
   - **Region:** אזור קרוב לישראל, למשל **Central EU (Frankfurt)**.
   - **Plan:** Free.
3. לחץ **Create new project** וחכה כדקה-שתיים עד שהפרויקט מוכן.

## שלב 2: הרצת הסכמה (הטבלאות והפונקציות)

1. בתפריט הצד: **SQL Editor** → **New query**.
2. פתח את הקובץ `supabase/schema.sql` מהתיקייה של המשחק, העתק את **כל** התוכן, והדבק בעורך.
3. לחץ **Run** (או Ctrl+Enter). צריך להופיע `Success. No rows returned`.

אפשר להריץ את הקובץ שוב בכל פעם שהוא מתעדכן. ההרצה בטוחה, לא מוחקת נתונים ולא משנה הגדרות שכבר שמרת.

הקובץ יוצר 6 טבלאות (`devices`, `sessions`, `events`, `feedback`, `app_config`, `admins`) ומפעיל עליהן הגנת RLS. שחקנים יכולים רק **לשלוח** נתונים דרך פונקציות מוגנות (עם בדיקות ומגבלת קצב). רק מנהל מחובר יכול **לקרוא** אותם. הדבר היחיד שפתוח לקריאה לכולם הוא `app_config`, כלומר ההגדרות שהמשחק צריך (פרסומות כבויות/פעילות, הודעה לשחקנים).

## שלב 3: יצירת משתמש מנהל

1. בתפריט הצד: **Authentication** → **Users** → **Add user** → **Create new user**.
2. הזן את המייל שלך וסיסמה חזקה.
3. **סמן את "Auto Confirm User"**. זה חובה: לוח הניהול מקבל רק משתמשים מאושרים.
4. לחץ **Create user**.
5. חזור ל-**SQL Editor**, הרץ את השורה הבאה עם המייל שלך:

   ```sql
   insert into public.admins(email) values ('you@example.com') on conflict do nothing;
   ```

   הערה: בסוף `supabase/schema.sql` כבר יש שורת `insert` כזו עם המייל של בעל המשחק. אם אתה נכנס עם המייל הזה, מספיק ליצור אותו כמשתמש (סעיפים 1-4). אם תיכנס עם מייל אחר, שנה את השורה בקובץ או הרץ את השורה למעלה.

   כדי להוסיף מנהל נוסף, חזור על סעיפים 1-5 עם המייל שלו. כדי להסיר מנהל: `delete from public.admins where email = 'x@example.com';`

6. **מומלץ מאוד:** כבה הרשמה פתוחה, כי מנהלים נוצרים רק ידנית.
   **Authentication** → **Sign In / Providers** (בגרסאות ישנות: **Providers** → **Email**) → כבה את **Allow new users to sign up** → **Save**.

## שלב 4: חיבור המשחק לשרת

1. בתפריט הצד: **Project Settings** → **API** (או **API Keys** / **Data API**, תלוי בגרסת הממשק).
2. העתק שני ערכים:
   - **Project URL**, משהו כמו `https://abcdxyz.supabase.co`
   - **anon public key** (מתחיל ב-`eyJ...`) **או** ה-**Publishable key** החדש (מתחיל ב-`sb_publishable_...`). שניהם עובדים.
   - ⚠️ **לעולם אל תעתיק את `service_role` / `secret` key** לקוד המשחק.
3. פתח את `js/config.js` והדבק:

   ```js
   const CONFIG_URL = 'https://abcdxyz.supabase.co';
   const CONFIG_ANON_KEY = 'eyJhbGciOi...';
   ```

4. העלה את מספר הגרסה בשני המקומות, למשל מ-`1.0.0` ל-`1.0.1`:
   - `APP_VERSION` בקובץ `js/config.js`
   - `VERSION` בקובץ `sw.js`

   שני המספרים חייבים להיות זהים, אחרת `publish.ps1` יעצור ויתריע.
5. הרץ `publish.ps1` (קליק ימני → Run with PowerShell, או `powershell -ExecutionPolicy Bypass -File .\publish.ps1`). אחרי דקה-שתיים GitHub Pages יתעדכן.

**האם מסוכן שהמפתח גלוי בקוד?** לא. ה-anon / publishable key נועד להיות ציבורי, וכל אפליקציית Supabase חושפת אותו בדפדפן. ההגנה על הנתונים היא ב-RLS ובפונקציות שבשלב 2: עם המפתח הזה אפשר רק לשלוח אירועים ומשובים (עם מגבלות), ולא לקרוא או למחוק כלום.

## שלב 6 (אופציונלי): קבלת כל משוב גם במייל

**בלי השלב הזה** המשובים מופיעים בלוח הניהול וזה מספיק. השלב הזה מוסיף מייל אוטומטי על כל משוב חדש. המייל נשלח דרך **Resend**, שירות שליחת מיילים עם חבילה חינמית (3,000 מיילים בחודש).

1. **חשבון Resend:** הירשם ב-https://resend.com **עם המייל שאליו אתה רוצה לקבל את המשובים**, ואשר את המייל.
   - בלי דומיין משלך, Resend שולח רק לכתובת שאיתה נרשמת, מהכתובת `onboarding@resend.dev`. זה בדיוק מה שצריך כאן.
   - אם בעתיד יהיה לך דומיין (למשל `hayeled.co.il`): ב-Resend → **Domains** → Add domain, והוסף את רשומות ה-DNS שהם נותנים. אחרי האימות אפשר לשלוח מכתובת כמו `feedback@hayeled.co.il`.
2. **מפתח API:** ב-Resend → **API Keys** → **Create API Key** (Permission: Sending access) → העתק את המפתח (מתחיל ב-`re_`). הוא מוצג רק פעם אחת.
3. **הפעלת pg_net ב-Supabase:** **Database** → **Extensions** → חפש `pg_net` → הפעל.
4. **שמירת הסודות ב-Vault** (מוצפן, לא בקוד): ב-**SQL Editor** הרץ, עם הערכים שלך:

   ```sql
   select vault.create_secret('re_xxxxxxxxxxxxxxxxx', 'resend_api_key');
   select vault.create_secret('you@example.com', 'feedback_email_to');
   -- רק אם אימתת דומיין ב-Resend:
   -- select vault.create_secret('feedback@your-domain.co.il', 'feedback_email_from');
   ```

   אם Vault לא מופעל: **Database** → **Extensions** → `supabase_vault` → הפעל (בפרויקטים חדשים הוא מופעל כברירת מחדל).
5. **בדיקה:** הרץ ב-SQL Editor משוב לדוגמה:

   ```sql
   select public.submit_feedback('test-device-0001', 5, 'בדיקת מייל 👋', null, '{"v":"test"}'::jsonb);
   ```

   תוך כדקה אמור להגיע מייל עם הנושא "משוב חדש (5★) - הילד מהשכונה" (בדוק גם בספאם). אחר כך מחק את משוב הבדיקה:
   `delete from public.feedback where device_id = 'test-device-0001';`
6. **אם לא הגיע מייל:** הרץ `select * from net._http_response order by created desc limit 5;` וראה את התשובה מ-Resend.
   - `401` / `403`: המפתח שגוי.
   - `422` / `validation_error`: ככל הנראה כתובת השולח או הנמען לא מאומתת.

   כדי לעדכן סוד, מחק אותו (`delete from vault.secrets where name = 'resend_api_key';`) וצור אותו מחדש. תקלה בשליחת מייל **אף פעם** לא מונעת שמירה של משוב.

**כיבוי:** מחק את הסוד `resend_api_key` מ-Vault, או כבה את `pg_net`.

## שלב 7 (אופציונלי): ניקוי אוטומטי של נתונים ישנים

כדי שהמסד יישאר קטן (מגבלת החבילה החינמית היא 500MB), אפשר למחוק אוטומטית אירועים גולמיים שגילם מעל 180 יום. המספרים הכלליים (שחקנים, משובים) לא נמחקים.

1. **Database** → **Extensions** → הפעל `pg_cron`.
2. הרץ שוב את כל `supabase/schema.sql`. הוא יזהה את pg_cron ויתזמן ניקוי יומי בשעה 03:15 (UTC).
3. בדיקה: `select * from cron.job;` אמורה להופיע משימה בשם `hy-retention`.

ניקוי ידני חד-פעמי: `select public.purge_old_events(180);`

## שלב 8: הפעלת פרסומות בעתיד

הכול נעשה מלוח הניהול → **הגדרות ופרסומות** → כרטיס **פרסומות**. השינוי מגיע לשחקנים בפתיחה הבאה של המשחק, בלי להעלות גרסה.

### אפשרות א': באנרים של ספונסרים (house). עובד מיד, בלי אישור של אף אחד

מתאים לספונסר מקומי (מסעדה, חנות ספורט, מועדון). אתה סוגר איתו מחיר ומעלה את הבאנר שלו.

1. סמן **פרסומות פעילות**.
2. **ספק:** "באנרים של ספונסרים (house)".
3. לחץ **+ הוסף באנר** ומלא:
   - **כתובת תמונה:** קישור `https://` לתמונה, למשל תמונה שהעלית ל-GitHub או ל-Imgur. גודל מומלץ: 640×160 לבאנר, ותמונה מרובעת או מאונכת למסך מלא.
   - **קישור בלחיצה:** האתר, האינסטגרם או הוואטסאפ של הספונסר (`https://wa.me/972...`).
   - **טקסט:** שורה קצרה, למשל "מסעדת השכונה, 10% הנחה לשחקנים!".
   - **משקל:** אם יש כמה באנרים, משקל גבוה יותר מקבל יותר הופעות.
   - **מיקומים:** איפה הבאנר יכול להופיע.
4. לחץ **שמור**. אמורה להופיע ההודעה "נשמר ✓".

**המיקומים:**
- **באנר במסך הבית:** פס קטן במסך הראשי.
- **מסך מלא בין מחזורים:** מופיע רק אחרי סיכום שבוע, **אף פעם לא באמצע משחק**. כפתור "סגור" נפתח אחרי 3 שניות. ברירת המחדל: לכל היותר פעם ב-4 מחזורים, לפחות 3 דקות בין פרסומות, ואף פעם לא ב-10 הדקות הראשונות של שחקן חדש.
- **פרסומת עם פרס:** כפתור "צפה בפרסומת וקבל +15 אנרגיה". השחקן בוחר לצפות, וזה מופעל רק כשמסמנים את התיבה. ברירת המחדל: עד 3 פעמים ביום.

החשיפות וההקלקות מופיעות בלוח הניהול, וזה גם נתון שאפשר להראות לספונסר. כשמכבים את "פרסומות פעילות", הכול נעלם מיד, בלי מקום ריק במסך.

### אפשרות ב': Google AdSense (הכנסה אוטומטית מגוגל)

לפני שזה אפשרי צריך:
1. **דומיין משלך** (למשל `hayeled.co.il`, בערך 50-100 ₪ לשנה), שמחובר ל-GitHub Pages: ב-GitHub → Settings → Pages → Custom domain, ורשומת DNS אצל רשם הדומיין. גוגל בדרך כלל לא מאשר כתובות `github.io`.
   ⚠️ מעבר לדומיין חדש פירושו כתובת חדשה, ולכן אחסון נפרד בדפדפן. לפני המעבר, הנחה את השחקנים לייצא "קוד גיבוי" בהגדרות ולייבא אותו בכתובת החדשה.
2. **אישור אתר** ב-https://adsense.google.com (הוספת האתר, ואז המתנה של כמה ימים עד כמה שבועות).
3. **מדיניות פרטיות** באתר, ו**הסכמת משתמש** לפרסומות מותאמות. המשחק מציג למשתמש מתג הסכמה בהגדרות כשהספק הוא AdSense, ובלי הסכמה הוא לא טוען את הסקריפט של גוגל.

אחרי האישור: בלוח הניהול בחר **ספק: Google AdSense**, הזן **Publisher ID** (`ca-pub-...`) ומזהי **Slot** (מספרים) לבאנר ולמסך המלא, ושמור. כשאין הסכמה או שהסקריפט נכשל, המשחק עובר לבאנרים של ספונסרים (אם יש) או לא מציג כלום. פרסומת עם פרס תמיד משתמשת בבאנרים של ספונסרים.

### עוד בלשונית "הגדרות ופרסומות"
- **הודעה לכל השחקנים:** טקסט קצר שמופיע בראש מסך הבית ("עדכון חדש: ליגה סעודית נוספה!"). שחקן שסגר הודעה לא יראה אותה שוב, עד שתשנה את הטקסט.
- **גרסאות ועדכונים:** אם תגדיר "גרסה אחרונה" גבוהה מהגרסה של השחקן, הוא יראה הודעת עדכון. "גרסה מינימלית" מציגה הודעת עדכון קבועה (לשימוש רק אם גרסה ישנה שבורה).
- **משוב:** כיבוי/הפעלה של שליחת משובים, ושל ההצעה לדרג אחרי עונה ראשונה ואחרי פרישה (לכל היותר פעם ב-30 יום לשחקן, עם כפתור "לא עכשיו").

## שלב 9: פרטיות (נוסח מוכן)

המשחק מציג לשחקנים בהגדרות את המתג **"שתף נתוני שימוש אנונימיים"** (מופעל כברירת מחדל) עם ההסבר:

> אנחנו אוספים נתונים אנונימיים בלבד (מזהה מכשיר אקראי, כמה זמן משחקים, אירועים במשחק) כדי לשפר את המשחק. בלי שם, בלי מיקום, בלי אנשי קשר.

**מה נאסף:**
- מזהה מכשיר **אקראי** שנוצר בדפדפן ואינו קשור לזהות.
- כניסות ומשך משחק.
- סוג מכשיר (אנדרואיד / אייפון / מחשב), שפת הדפדפן, גרסת המשחק, והאם המשחק מותקן.
- אירועים במשחק: התחלת קריירה (לאום, עמדה, מועדון), משחקים, עונות, העברות, תארים, פרישה, חשיפות והקלקות על פרסומות, ותקלות טכניות.
- **משוב שהשחקן בחר לשלוח:** דירוג, טקסט, ואימייל רק אם השאיר אותו.

**מה לא נאסף:** שם השחקן האמיתי (השם שבוחרים לשחקן במשחק לא נשלח), מיקום, אנשי קשר, תמונות. אין עוגיות פרסום, כל עוד AdSense לא מופעל.

**שמירה:** אירועים גולמיים נמחקים אחרי 180 יום (אם הופעל שלב 7).

**ביטול:** כיבוי המתג בהגדרות עוצר מיד את כל השליחה ומוחק את מה שממתין לשליחה במכשיר. המשחק ממשיך לעבוד כרגיל.

**התקדמות המשחק** (הקריירה, היכל התהילה) **לא נשלחת לשרת בכלל.** היא נשמרת רק במכשיר של השחקן.

אם תפעיל AdSense, תצטרך דף מדיניות פרטיות מלא שמזכיר גם את גוגל ואת העוגיות שלה.

## שלב 10: פתרון תקלות

| מה רואים | מה לעשות |
|---|---|
| "הבקאנד עוד לא מוגדר" בלוח הניהול | `js/config.js` עדיין ריק, או שהגרסה החדשה עוד לא עלתה. בצע את שלב 4, חכה 2 דקות ורענן (Ctrl+F5). |
| "אימייל או סיסמה שגויים" | בדוק ב-Authentication → Users שהמשתמש קיים. אפשר לאפס סיסמה דרך ⋮ → Send password recovery, או למחוק וליצור מחדש. |
| "למשתמש הזה אין הרשאת מנהל" | המייל לא נמצא בטבלת `admins` (שלב 3, סעיף 5; בדוק שאין רווחים או טעות כתיב), **או** שהמשתמש לא אושר (צור אותו מחדש עם Auto Confirm). |
| שגיאה 401 / "Invalid API key" | המפתח ב-`config.js` שגוי או חלקי. העתק שוב את anon / publishable key (לא service_role). |
| "הפונקציות לא נמצאו בשרת" | הסכמה לא הורצה, או שהורצה חלקית. הרץ שוב את כל `supabase/schema.sql`. |
| "אין חיבור לשרת" | אין אינטרנט, או ש**הפרויקט החינמי הושהה**: Supabase משהה פרויקט חינמי אחרי 7 ימים בלי פעילות. היכנס ל-https://supabase.com/dashboard ולחץ **Restore project**. כל עוד יש שחקנים פעילים זה לא קורה. בזמן ההשהיה **המשחק ממשיך לעבוד**, והאירועים והמשובים נשמרים בתור במכשירים ונשלחים כשהשרת חוזר. |
| שגיאת CORS בקונסול | בדרך כלל זה בעצם 401 או כתובת שגויה. ודא שה-URL הוא בדיוק `https://xxxx.supabase.co`, בלי `/rest/v1` בסוף. |
| המספרים לא זזים | ודא שהגרסה עם `config.js` המעודכן עלתה, ושבמכשיר הבדיקה המתג "שתף נתוני שימוש אנונימיים" פעיל. השחקן צריך לרענן את המשחק פעם אחת כדי לקבל את הגרסה החדשה. |
| באנר לא מופיע אחרי שמירה | המשחק טוען הגדרות בפתיחה: סגור ופתח את המשחק. ודא שסימנת "פרסומות פעילות", שהספק הוא house, ושלבאנר יש כתובות `https://` תקינות (שורה אדומה פירושה כתובת לא תקינה). |

**בדיקה מקומית בלי שרת אמיתי (למפתחים):** `node tests/mock-supabase.mjs 54321` מריץ שרת מדומה עם המנהל `admin@test.local` / `test1234`. בקונסול של הדפדפן הרץ
`localStorage.setItem('hy.dev.backend', JSON.stringify({url:'http://localhost:54321', anonKey:'mock-anon'}))` ורענן. כדי לחזור לשרת האמיתי: `localStorage.removeItem('hy.dev.backend')`.
